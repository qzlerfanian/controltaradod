# معماری سامانه راهبند

## مرزبندی سرویس‌ها

نسخه نخست به‌صورت یک **modular monolith** اجرا می‌شود. این انتخاب استقرار در هر سایت را ساده نگه می‌دارد، ولی مرز ماژول‌ها اجازه می‌دهد بعداً پردازش دوربین یا API جداگانه اجرا شود.

1. `camera`: اتصال RTSP، reconnect و دریافت آخرین فریم هر دوربین
2. `inference`: مدل موجود OpenVINO برای تشخیص پلاک و کاراکترها
3. `recognition`: رأی‌گیری چندفریمی، اعتبارسنجی و حذف تشخیص تکراری
4. `access`: جست‌وجوی مالک و بررسی ستون `Access`
5. `relay`: بازکردن راهبند و تمدید deadline به‌ازای هر پلاک مجاز جدید
6. `events`: ثبت SQL Server، ذخیره تصویر و انتشار MQTT
7. `api`: REST و WebSocket برای رابط React
8. `frontend`: داشبورد RTL مخصوص نمایشگر دسکتاپ

## جریان رویداد

```text
RTSP camera
  -> bounded frame buffer
  -> OpenVINO inference
  -> plate normalization and temporal voting
  -> duplicate policy
  -> owner/access lookup in local SQL Server
  -> durable local event outbox
  -> SQL Server log + MQTT publish + WebSocket broadcast
  -> relay coordinator (only when Access = 1)
```

## دوربین

هر دوربین یک شناسه پایدار و تنظیمات مستقل دارد:

- نام نمایشی
- RTSP URL از secret/environment
- جهت `entry` یا `exit`
- ROI مستقل
- فعال/غیرفعال
- نرخ نمونه‌برداری
- آستانه‌های تشخیص
- رله وابسته

افزودن دوربین نیازمند تغییر کد نیست. محدودیت عملی تعداد دوربین با benchmark سخت‌افزار و latency مدل تعیین می‌شود.

## قرارداد رله

رله از callback تشخیص جداست و تنها یک coordinator مجاز به کنترل آن است.

- پلاک غیرمجاز: بدون فرمان رله
- اولین پلاک مجاز: ارسال پالس و تعیین deadline پانزده‌ثانیه‌ای
- پلاک مجاز هنگام بازبودن: ارسال پالس جدید و `deadline = now + 15s`
- پایان deadline: فقط پایان وضعیت منطقی backend؛ بسته‌شدن فیزیکی بر عهده برد است
- خطای رله: ثبت structured log و نمایش health در داشبورد؛ رویداد پلاک حذف نمی‌شود

درایور واقعی NRC پشت interface قرار می‌گیرد تا تست بدون سخت‌افزار ممکن باشد.

## دیتابیس

جدول مالکین `[IMPDb].[CTV].[tbCars]` و جدول رخداد
`[IMPDb].[TEL].[tbPlateLogs]` بدون تغییر حفظ می‌شوند. کلید استاندارد تطبیق پلاک از چهار بخش ساخته می‌شود:

`Two + normalized(Alpha) + Three + City`

ستون `Access` مرجع اجازه خودکار است. مقدار `NULL` یا `0` غیرمجاز تلقی می‌شود. تمام queryها پارامتری و در repository متمرکز خواهند بود.

## حذف تشخیص تکراری

پس از پذیرش یک پلاک، کلید نرمال‌شده آن در deduplicator سراسری سایت ثبت می‌شود. در پنجره پیش‌فرض ۲۰ ثانیه، همان پلاک از هر دوربین و هر جهت دیگری نادیده گرفته می‌شود؛ بنابراین ثبت خروج بلافاصله به‌عنوان ورود تکرار نخواهد شد. این زمان از تنظیمات سایت قابل تغییر است.

## پایداری

- buffer دوربین bounded است تا تأخیر انباشته نشود؛ فریم قدیمی کنار گذاشته می‌شود.
- هر دوربین state مستقل دارد و global مشترک ندارد.
- event outbox محلی مانع حذف رویداد هنگام قطع MQTT/SQL Server می‌شود.
- shutdown سرویس graceful است.
- health شامل دوربین‌ها، inference، دیتابیس، MQTT، فضای دیسک و رله است.
- systemd با کاربر محدود اجرا می‌شود، نه `root`.
